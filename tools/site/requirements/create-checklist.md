# 创建清单的要求

请根据我提供的主题，创建一份可导入「速记清单」的 Markdown 备忘清单，适合手机速查、卡片阅读和自测。

## 我会补充的信息

- 主题：要整理的知识、工具或操作流程。
- 读者与范围：入门或进阶、需要覆盖的内容。
- 版本与环境：涉及软件时说明版本、系统或运行环境。
- 参考材料：可选，优先依据我提供的资料或官方文档。

如果主题尚未提供，请先询问主题；必要信息缺失且会影响内容正确性时，集中询问。其余内容采用合理默认值，并在清单简介中说明适用范围。默认使用简体中文。

## 交付内容

输出一个 UTF-8 编码的 `.md` 文件。文件正文直接从一级标题开始，内容是完整清单；如支持文件附件，提供可下载文件，否则直接输出 Markdown 原文，保留正文内部的代码围栏。

## 结构与格式

1. 使用一个 `# 清单标题`，接着用一小段简介说明用途、适用版本和前提。
2. 使用 `## 章节` 按场景组织知识点，使用 `### 知识点` 为表格、命令或短说明提供标题。标题应清晰具体。
3. 每个知识点围绕一个可查阅的问题展开，优先使用短段落、简单列表和标准 Markdown 表格。
4. 对命令、语法、快捷键或术语使用两列或三列表格：第一列是提示或问题，其余列是答案、解释或例子。每行应独立可读，便于应用隐藏后续列进行自测。
5. 表格包含表头和 `---` 分隔行，单元格保持单行；单元格中的竖线写成 `\|`，代码使用行内反引号。
6. 多行示例使用成对闭合的三个反引号代码围栏，标注 `bash`、`python` 等语言；每个示例说明必要前提，命令与解释分开。
7. 内容以标准 Markdown 文本、表格、列表、链接和代码块表达；仅靠这些内容即可完整理解清单。使用普通标题层级，保持简单列表结构。
8. 参考链接使用完整的 HTTP(S) 地址。重要信息同时写在正文中，让文件离线阅读时仍可使用。

## 内容质量

- 优先整理高频、实用、可核对的知识，明确区分命令、参数、输入与输出。
- 示例应在声明的版本和环境中成立；占位符使用清晰的名称，并解释其替换方式。
- 涉及删除、覆盖、权限或生产变更的命令，紧邻示例说明影响范围与执行前提。
- 事实依据来自提供的材料或可验证来源；有不确定性时明确标记。仅在实际运行后写“已验证”。
- 文末列出主要参考链接和适用版本。根据主题合理确定篇幅，避免重复条目。

## 格式示例

以下只是结构示例。实际交付应围绕我指定的主题撰写。

````markdown
# Git 日常速查

适用于已安装 Git 的本地仓库，整理查看工作区与历史记录的常用操作。

## 工作区

### 查看改动

| 需求 | 命令 | 说明 |
| --- | --- | --- |
| 查看状态 | `git status` | 显示暂存区与工作区状态 |
| 查看未暂存改动 | `git diff` | 显示工作区相对暂存区的差异 |

## 历史记录

### 查看最近提交

在 Git 仓库目录内执行：

```bash
git log -5 --oneline
```

## 参考资料

- [Git 官方文档](https://git-scm.com/docs)
````

## 输出前自检

确认只交付一份完整的 Markdown 清单；标题层级清楚，表格列数一致，代码围栏闭合，示例有必要前提，参考链接与内容对应。清单可通过应用的“导入本地 Markdown”使用；托管为可直接获取正文的 `.md` 链接后，也可通过“添加在线 Markdown”使用。
